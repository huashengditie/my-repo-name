The seizure-detection pipeline: design, parameters, and results

A complete, parameter-level account of the pathway built for patient-independent scalp-EEG seizure detection — from raw EDF audit through a Standard 1D CNN — evaluated on the current 11-subject CHB-MIT archive, with a discussion of what the numbers do and don't show.

Prepared 2026-09-06 Archive chb01–chb11, 236 EDF, 43 seizures Branch ralph/cnn-main-network Reference plan Grand Development Plan.md
§1

Overview

The task is binary window classification: does a 4-second slice of 23-channel scalp EEG contain seizure activity? The pipeline turns raw .edf recordings into that decision through nine deterministic stages, each frozen into a config file or module so the whole chain can be re-run byte-for-byte from the same inputs. Two model families sit at the end of the chain — classical spectral-feature classifiers (logistic regression, random forest) and a Standard 1D CNN that reads the filtered waveform directly.

Every design choice below traces back to one governing rule: a subject's data lives in exactly one of train, validation, or test — never split across them. Scalp-EEG signal morphology varies enormously between patients, so a random window-level split would let the model memorize a subject's idiosyncrasies rather than learn seizure signal, and would report an optimistic score that collapses on a genuinely new patient. Every number in §4 was produced under that constraint.

§5

Discussion

Performance in context

A 40,513-parameter CNN reading raw filtered voltage lands within 0.11 AUROC of a random forest built on hand-engineered spectral features, and ahead of logistic regression on the same features. That is a reasonable outcome for a first "standard" architecture, not a disappointing one — the Grand Development Plan frames the Standard CNN as a pipeline sanity check, with the parameter-efficiency argument reserved for the Compact CNN still to come. The relevant comparison ahead is not "which model has the highest AUROC" but "how much AUROC does the compact model give up per parameter and per millisecond of inference it saves."

The fold 2 anomaly

Fold 2 holds out chb02, chb04, and chb08 for testing, and its validation subjects are chb06 and chb07. Its specificity of 0.0096 means the validation-selected threshold, applied to these three unseen subjects, classifies almost every window positive. Two candidate explanations follow directly from the design: chb08 alone contributes 462 of the fit set's positive windows — over five times chb02's 88 — so the pos_weight this fold computed (328.9, the highest of the five folds) was tuned against a fit-subject mix that does not resemble fold 2's held-out subjects. And because the decision threshold is fixed by Youden's J on chb06/chb07 alone, it inherits whatever operating point suits those two subjects, with no guarantee it transfers to chb02/04/08's signal amplitude or noise floor. This is a concrete illustration of the patient-variability problem the pipeline is built to expose, not to hide behind a single averaged number.

Patient variability, not pipeline instability

Sensitivity and specificity both carry standard deviations near 0.18–0.20 across folds — larger than the deviation on AUROC itself. Gate E's own instability check (no NaN/Inf loss, loss strictly decreasing) passes cleanly on every fold; the variability lives in which subjects a fold happens to test on, not in unstable training. That distinction matters for how the numbers should be read: a single mean AUROC understates how differently the current model behaves from one held-out patient to the next, which is precisely the generalization gap the wider seizure-detection literature keeps flagging as unresolved.

Sensitivity to archive size

The same pipeline, same seed, same architecture, run first on 6 subjects and then on 11, moved mean CNN AUROC from 0.6413 to 0.7993 and tightened the standard deviation from 0.1786 to 0.0964. Neither number should be treated as a settled estimate of this model's ceiling — both are a function of how much of the ~24-subject archive is currently on disk. The pipeline is built to re-derive every one of these figures automatically whenever the archive grows again (see CLAUDE.md's re-run discipline), so the expectation going forward is that this table keeps moving, not that it has converged.

What this report cannot yet claim

Every metric above is a window-level statistic: is this isolated 4-second slice seizure or not. It says nothing yet about the metric that actually matters for a wearable or bedside monitor — false positives per hour of continuous recording, and whether contiguous positive windows correctly merge into one detected seizure event rather than being counted seizure-by-seizure or window-by-window. That event-level scoring stage (C-EVENT in the development plan) has not been built yet, so no statement here should be read as a claim about real-world alarm burden.

Threats to validity

The archive is 11 of roughly 24 subjects, so class balance, per-subject seizure counts, and fold composition are all provisional. Six of the 236 records were read through an MNE fallback path rather than strict EDF-compliant parsing (a documented, legitimate CHB-MIT quirk, not corruption) — their header metadata is trusted, but they represent a slightly lower-confidence subset. No external dataset (TUSZ) has been evaluated, so nothing here speaks to cross-institution generalization.

Where this points next

Gate E's pass unlocks the Compact CNN (C-LITE) under the identical protocol documented in §3 — same splits, same loss policy, same threshold rule — so that its accuracy-vs-efficiency trade-off against this Standard CNN is measured on a like-for-like basis. Fold 2's collapse is worth a direct look before that comparison is trusted: whether a different pos_weight cap, a validation set drawn from more than two subjects, or simply the archive's continued growth resolves it.
